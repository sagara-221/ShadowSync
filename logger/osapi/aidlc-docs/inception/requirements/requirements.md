# 要件定義書: OS API ロガーツール

## 1. インテント分析の概要
- **ユーザーリクエスト**: アクティビティログ自動集計システム「ShadowSync」のクライアント側エージェントを作成する。
- **リクエストの種類**: 新規プロジェクト (Greenfield)
- **スコープの推定**: 単一コンポーネント (logger/osapi)
- **複雑さの推定**: 中程度 (OS APIのフック、MQTT通信、オフラインキューイングを含むため)

## 2. 機能要件
- **アクティビティ監視**:
  - アクティブウィンドウの切り替えを監視し、切り替わったウィンドウの**タイトル**および**プロセス名**を取得する。
  - キーボードおよびマウスの入力アクティビティを監視する。
  - **オーディオ監視**: OSのAudio Session APIを利用し、現在音声を再生・録音しているセッションの一覧、各セッションのプロセス名、Session ID、および音量レベル(Peak Meter)を取得する。
  - アクティビティのメトリクス: 指定された一定間隔内に何らかの入力があったかどうかの真偽値（アクティブ / 非アクティブ）。
  - プライバシー保護の観点から、生のキーストロークは絶対に取得しないこと。
- **データフォーマット**:
  - 収集したアクティビティログを、`data-accumulation` サービスと協調して定義されたスキーマに従い、JSON形式にフォーマットする。
- **データ送信**:
  - X.509デバイス証明書を使用し、MQTT経由でAWS IoT Coreへデータを送信する。
  - **送信タイミング**: 
    - アクティブウィンドウが変更されるたび
    - Audio Sessionが追加または削除されるたび
    - 5分間隔（定期スナップショット取得）
- **オフライン対応**:
  - ネットワークが切断された場合、データをローカルにキューイングする (例: SQLiteやローカルファイルを使用)。
  - **オフラインキューの容量**: 時間ベースの保持 (例: 過去7日分のログのみ保存し、古いログから破棄)。
  - ネットワークが復旧した際、キューイングされたデータを自動的に再送する。
- **マルチテナント対応**:
  - アプリケーション設定等で対象の `user_id` を保持できるようにする。
  - クラウドへ送信するデータ（ペイロードやMQTTトピック）には、必ず対象の `user_id` を付与して送信する。

## 3. 非機能要件
- **実行環境**: Windowsネイティブ環境。バックグラウンドプロセスとして常に実行されること。
- **リソース制約**: CPUおよびメモリの消費量を厳密に最小限に抑えること。
- **技術スタック**: Pythonを推奨 (OSフック用に `psutil` や `pywin32` などのライブラリを使用) するが、最終的な選択は効率性に基づいて開発者が決定してよい。

## 4. 適用された拡張ルールの設定
- **セキュリティベースライン**: スキップ (適用なし)
- **プロパティベーステスト (PBT)**: 部分的適用 (純粋関数およびシリアライズのラウンドトリップに対してのみ強制)

## 5. 概要
`osapi` ロガーツールは、ShadowSyncシステムの軽量なWindowsバックグラウンドエージェントとして機能します。ユーザーのアクティビティ (ウィンドウの切り替えによるタイトル・プロセス名の取得と、入力の有無の真偽値) を、機密性の高いキーストロークを取得することなく継続的に監視します。イベントはJSON形式で即座にAWS IoT Coreへ送信されます。ネットワーク障害が発生した場合は、ログはローカルに最大7日間キューイングされ、回復時に同期されます。これらすべての処理を最小限のシステム負荷で実行します。
