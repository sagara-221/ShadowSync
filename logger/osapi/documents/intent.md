# 子AI-DLC向け 開発指示書: OS API ロガーツール

## 1. プロジェクトの目的と全体コンテキスト (Context)
* **概要**: 個人活動ログ自動集計・活用システム「ShadowSync」のクライアント側エージェントの一つ。
* **役割**: Windows PC上でユーザーが「今どのアプリケーションを使っているか」「どれくらいアクティブに操作しているか」を監視し、クラウド（AWS）へ送信する。

## 2. 機能要件 (Functional Requirements)
* **アクティビティ監視**: アクティブウィンドウの切り替えイベント、またはキーボード・マウスの入力アクティビティレベル（回数など）を取得すること。
* **データ送信**: 取得したログ情報をJSON形式にまとめ、AWS IoT CoreへMQTT通信で送信すること。
* **オフライン対応**: ネットワーク切断時や送信失敗時には、ローカル（SQLiteやファイル等）にデータを一時的にキューイングし、復旧時に再送する仕組みを実装すること。
* **マルチテナント対応**: アプリケーション設定等で対象の `user_id` を保持できるようにし、クラウドへ送信するデータ（ペイロードやMQTTトピック）には必ず対象の `user_id` を付与して送信すること。

## 3. 非機能要件と技術的制約 (Non-Functional & Constraints)
* **実行環境**: Windowsネイティブ環境。常にバックグラウンドで動作させること。
* **推奨技術**: OS APIへのフックが容易な Python (例: `psutil`, `pywin32`) などを推奨するが、AI-DLC側で最適と判断したものを採用してよい。
* **運用要件**: CPU・メモリなどのシステムリソース消費を最小限に抑えること。

## 4. 外部インターフェースと境界 (Interfaces & Boundaries)
* **通信プロトコル**: AWS IoT Core (MQTT)
* **認証方式**: X.509デバイス証明書によるMQTTS通信（ローカルに証明書を配置）。
* **スキーマ設計**: 詳細なJSONスキーマ（ペイロード）の設計は本AI-DLC自身、および `data-accumulation` 側と協調して決定すること（親からの強制はしない）。
* **参照資料**: `../../aidlc-docs/inception/application-design/data-accumulation-interface.md`

## 5. スコープ外 (Out of Scope)
* 取得したログ情報の「分析」や「要約」は行わない（すべてバックエンド側で行う）。
* 入力されたキーの生の文字列（キーロガーとしての機能）はプライバシー保護のため取得しない。
