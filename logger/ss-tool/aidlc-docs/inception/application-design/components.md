# Components — ss-tool (Screenshot Logger)

## コンポーネント一覧

### 1. ScreenCapture
- **責務**: アクティブウィンドウの画像キャプチャとWebP変換
- **概要**: Win32 APIを用いてフォアグラウンドウィンドウの内容を取得し、WebP形式にエンコードする。キャプチャ完了後、内部イベントバスへ `CaptureCompleted` イベントを発行する。

### 2. WindowMonitor
- **責務**: アクティブウィンドウの切替検知（イベント駆動）
- **概要**: `SetWinEventHook` (EVENT_SYSTEM_FOREGROUND) を用いてウィンドウ切替をリアルタイム検知する。デバウンス処理（1〜2秒）を内蔵し、短時間の連続切替を抑制。切替検知時に `WindowChanged` イベントを発行する。

### 3. PeriodicScheduler
- **責務**: 定期撮影タイマーの管理
- **概要**: 設定ファイルで指定された間隔（デフォルト5分）でタイマーを発火し、`PeriodicTick` イベントを発行する。

### 4. EventBus
- **責務**: コンポーネント間の非同期イベント仲介
- **概要**: Python `queue.Queue` ベースの内部イベントバス。各コンポーネントはイベントを発行・購読し、疎結合な非同期パイプラインを実現する。

### 5. QueueManager
- **責務**: 未送信タスクの永続化キュー管理
- **概要**: SQLiteをバックエンドとした永続キュー。キャプチャされた画像のローカルパスとメタデータを管理し、送信状態（pending/uploading/sent/failed）をトラッキングする。プロセス再起動後もキューを復元可能。

### 6. S3Uploader
- **責務**: Presigned URLを取得し、S3へ画像をアップロード
- **概要**: AWS IoT Core Request/Response経由でバックエンドのPresigned URL発行LambdaへURL発行を依頼し、HTTPSのPUTリクエストで画像をS3にアップロードする。アップロード成功後、`UploadCompleted` イベントを発行する。

### 7. MqttPublisher
- **責務**: メタデータのMQTTS送信
- **概要**: AWS IoT Core に X.509証明書認証で接続し、撮影メタデータ（S3パス、タイムスタンプ、ウィンドウ情報等）をJSON形式でMQTTSパブリッシュする。送信成功後、`MetadataSent` イベントを発行する。

### 8. StorageManager
- **責務**: ローカルストレージの容量監視と管理
- **概要**: オフライン一時保存ディレクトリの使用量を監視し、ユーザー設定の容量上限に到達した場合は最も古い未送信画像から削除する。送信完了済み画像の即時削除も担当する。

### 9. ConfigManager
- **責務**: 設定ファイルの読み込みと管理
- **概要**: JSON/YAML形式の設定ファイルから `user_id`, `device_id`, 撮影間隔, 容量上限, AWSエンドポイント, 証明書パス等を読み込み、各コンポーネントへ設定値を提供する。

### 10. ServiceHost
- **責務**: Windowsサービスとしてのライフサイクル管理
- **概要**: `pywin32` (win32serviceutil) を用いてWindowsサービスとして登録・起動・停止する。サービス停止シグナルの受信と各コンポーネントの安全なシャットダウンを制御する。

### 11. Logger
- **責務**: アプリケーションログの出力管理
- **概要**: Python標準 `logging` モジュールを使用し、ファイルローテーション付きでログを出力する。各コンポーネントが統一的なロガーインスタンスを利用する。
