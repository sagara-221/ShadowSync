# 子AI-DLC向け 開発指示書: スクリーンショット取得 ロガーツール

## 1. プロジェクトの目的と全体コンテキスト (Context)
* **概要**: 個人活動ログ自動集計・活用システム「ShadowSync」のクライアント側エージェントの一つ。
* **役割**: ユーザーの画面の視覚的情報（スクリーンショット）を定期的に取得し、クラウド（AWS）へ送信する。

## 2. 機能要件 (Functional Requirements)
* **SS取得**: 定期的なインターバル、または特定のトリガーで画面のスクリーンショットを撮影すること。
* **データ送信の分離**:
  1. 画像本体は大容量であるため、S3へ直接アップロード（Presigned URL等を利用）すること。
  2. S3のパスや撮影時のメタデータをJSONにまとめ、AWS IoT CoreへMQTTで送信すること。
* **オフライン対応**: 送信失敗時はローカルディスクに画像を一時保存し、復旧時に順次アップロード・送信を行うこと。
* **マルチテナント対応**: アプリケーション設定等で対象の `user_id` を保持できるようにし、クラウドへ送信するデータ（S3パスやMQTTのメタデータ）には必ず対象の `user_id` を付与して送信すること。

## 3. 非機能要件と技術的制約 (Non-Functional & Constraints)
* **実行環境**: Windowsネイティブ環境。
* **運用要件**: ローカルディスクの容量を圧迫しないよう、送信完了後の画像削除や、一時保存容量の上限を設定すること。画像の圧縮処理も検討すること。

## 4. 外部インターフェースと境界 (Interfaces & Boundaries)
* **通信プロトコル**: AWS IoT Core (MQTT) および Amazon S3 (HTTPS)
* **認証方式**: X.509デバイス証明書によるMQTTS通信（メタデータ送信）。画像アップロードはIAM（またはPresigned URL等）を利用。
* **スキーマ設計**: 詳細なJSONスキーマの設計は本AI-DLC自身で決定すること。
* **参照資料**: `../../aidlc-docs/inception/application-design/data-accumulation-interface.md`

## 5. スコープ外 (Out of Scope)
* 画像に対するOCR（文字認識）や画像解析・タグ付けは一切行わない（すべてバックエンド側で行う）。
