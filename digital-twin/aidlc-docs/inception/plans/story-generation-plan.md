## 3. ストーリー分解方針

### 推奨方針: ユーザージャーニー中心、機能グループ併用

ストーリーは、digital-twinの主要ユーザージャーニーに沿って整理する。

1. 認証してデスクトップアプリを開く。
2. 過去の活動について質問する。
3. `user_id` によって安全に活動コンテキストを検索する。
4. Bedrock Novaで回答を生成する。
5. 回答の根拠と参照元を表示する。
6. 会話履歴を保存し、後から再利用する。
7. 失敗系とアクセス拒否を扱う。

このジャーニーの中で、以下の機能領域に分ける。
- デスクトップクライアント
- 認証とユーザーコンテキスト
- 会話
- 検索
- 回答生成
- 根拠表示
- 会話履歴
- セキュリティと監査

### 検討した代替方針

- **機能中心**: エンジニアリング上の分解には向くが、エンドツーエンドのユーザー体験が弱くなりやすい。
- **ペルソナ中心**: ステークホルダー別の整理には向くが、digital-twinの中心フローが重複しやすい。
- **ドメイン中心**: 境界づけられた文脈の整理には有効だが、ユーザー視点のレビューにはやや直感的でない。
- **Epic中心**: バックログ階層には向くが、inception段階では実装寄りになりすぎる可能性がある。

各ストーリーは次の形式で記述する。

```markdown

**利用者として** [ペルソナ]  
**したいこと** [能力]  
**目的** [成果]

### 受け入れ条件
- 前提: [状況]。操作: [行動]。結果: [期待結果]。

### 補足
- 要件トレース: [FR/NFR ID]
- セキュリティ考慮: [該当する場合]
- PBT考慮: [該当する場合]
```

## 5. 計画質問と回答

### 質問1: 主ペルソナ
最初に最も重視する利用者像はどれですか？

A) 個人ユーザー本人。自分の過去の作業・思考・活動を検索したい  
B) 複数ユーザーを管理する管理者。利用状況やセキュリティを重視したい  
C) 開発者・運用者。システム検証、障害調査、品質維持を重視したい  
D) Aを主、B/Cを補助ペルソナとして扱う  
X) その他

[Answer]: A

### 質問2: ストーリー粒度
ストーリーの粒度はどれを希望しますか？

A) 大きめのEpic中心。全体像を把握しやすくする  
B) 中粒度の実装可能ストーリー中心。後続工程に接続しやすくする  
C) 細かめの受け入れテスト単位。検証観点を厚くする  
D) Epicと中粒度ストーリーを併記する  
X) その他

[Answer]: A

### 質問3: 対話体験の優先事項
対話体験で最も重視する観点はどれですか？

A) 回答の速さ  
B) 回答の正確性と根拠の明確さ  
C) 会話の継続性と履歴活用  
D) セキュリティと他ユーザー情報の混入防止  
X) その他

[Answer]: B

### 質問4: 根拠表示の詳細度
回答根拠の表示ストーリーは、どの詳細度で作成しますか？

A) 最低限の参照元一覧だけ  
B) 回答文と根拠を対応付けて表示する前提  
C) 時系列、ソース種別、関連抜粋まで表示する前提  
D) 初期はCを目標にし、実装難度に応じて段階化する  
X) その他

[Answer]: D

### 質問5: 失敗系シナリオ
失敗系・例外系ストーリーはどの範囲まで含めますか？

A) 認証失敗、検索失敗、LLM失敗のみ  
B) Aに加えて、根拠不足、タイムアウト、履歴保存失敗を含める  
C) Bに加えて、権限違反、他ユーザーデータ混入防止、監査ログ確認を含める  
D) 失敗系は後続の設計フェーズで扱う  
X) その他

[Answer]: C

### 質問6: 受け入れ条件の形式
受け入れ条件の形式はどれを希望しますか？

A) 箇条書きの条件  
B) Given/When/Then形式  
C) 箇条書きとGiven/When/Thenの併用  
D) テスト観点とユーザー観点を分けて記載  
X) その他

[Answer]: C

### 質問7: セキュリティストーリー
セキュリティ関連をどのようにストーリー化しますか？

A) 各機能ストーリーの受け入れ条件に含める  
B) セキュリティ専用ストーリーとして独立させる  
C) AとBを併用する  
D) Security Baselineの後続設計で扱い、User Storiesでは最小限にする  
X) その他

[Answer]: C

### 質問8: PBTトレース
Property-Based Testingにつながる観点をUser Storiesに含めますか？

A) 含める。検索条件、`user_id` 分離、シリアライズなどを補足に明記する  
B) 最小限だけ含める。詳細は機能設計で扱う  
C) User Storiesでは含めない  
X) その他

[Answer]: B
